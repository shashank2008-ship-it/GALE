# Week 6: LLM Evaluation & Baseline Benchmarking with Golden Dataset

## 1. Overview
Week 6 establishes an **Automated Baseline Evaluation Pipeline** to systematically test, score, and benchmark LLM responses against a curated "Golden Question Set" (`golden_set.json`).

The evaluation harness:
1. Loads 10 curated domain questions covering tokens, algorithms (BPE, WordPiece, SentencePiece), and token economics.
2. Sends each question to a local LLM (Ollama `llama3.2`) with `temperature: 0` for reproducible deterministic outputs.
3. Computes automated **Keyword Coverage Scoring** based on expected technical terms.
4. Classifies responses into `PASS` ($\ge 60\%$ keyword coverage) or `REVIEW` ($< 60\%$).
5. Saves detailed evaluation records to a CSV file (`baseline_results.csv`) for version tracking.
6. Prints a statistical summary of the evaluation run.

## 6. Evaluation Scoring Methodology

For each test question:
$$\text{Keyword Coverage Score (\%)} = \left( \frac{\text{Number of Matched Keywords}}{\text{Total Expected Keywords}} \right) \times 100$$

- **`PASS`**: Score $\ge 60\%$
- **`REVIEW`**: Score $< 60\%$
- **`ERROR`**: Request failed or network timeout

### Output CSV Schema (`baseline_results.csv`):
| Field | Description |
| :--- | :--- |
| `Question_ID` | Identifier from golden set (e.g., `Q001`) |
| `Question` | Input prompt sent to the LLM |
| `Expected_Answer` | Human-curated ground truth answer |
| `LLM_Answer` | Raw response returned by Ollama |
| `Matched_Keywords` | Comma-separated list of successfully identified keywords |
| `Missing_Keywords` | Comma-separated list of keywords not found in the response |
| `Score` | Keyword coverage percentage |
| `Status` | `PASS`, `REVIEW`, or `ERROR` |
| `Source` | Reference documentation URL |
| `Model` | Evaluated LLM (`llama3.2`) |
| `Release` | Dataset/prompt release tag (`v0.1`) |

## 7. Troubleshooting
- **`requests.exceptions.ConnectionError: ... Connection refused`**:
  Make sure the Ollama daemon is running (`ollama serve`) and accessible at `http://localhost:11434`.
- **`404 Client Error: model 'llama3.2' not found`**:
  Run `ollama pull llama3.2` to ensure the model weights are downloaded locally.
- **Encoding Issues in CSV**: The script uses `utf-8-sig` encoding so that special characters and symbols open cleanly in Microsoft Excel.
